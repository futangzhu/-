# 记忆与生活线（astrbot_plugin_life_memory）

给一个 AstrBot 里的 AI 角色加一条**生活线**：她今天有安排、记得住人、会自己挑时候开口，
晚上会写日记。不是"到点必回"的闹钟，也不是"什么都能记住"的数据库。

- 作者：tangzhu
- 版本：1.0.0
- 依赖：AstrBot 4.x / Python 3.10+ / **无第三方库**（只用标准库 + AstrBot 自带依赖）
- 需要一个可用的 LLM 提供商（`context.get_using_provider()` 能拿到即可）

---

## 一、它到底做什么

| 能力 | 说明 |
|---|---|
| **今天怎么过** | 每天用模型排一份日程（醒来、上班、发呆、睡下），存成 `life_day` / `life_block`。聊天时把"此刻在做什么"补进 system_prompt |
| **她记得的** | 从对话里抽事件记忆（谁、什么事、什么情绪、什么关键词、什么时候过期），按人和重要度存 |
| **记忆注入** | 每次要开口前，按当前说话人 + 这句话检索最多 3 条记忆（**80 字预算**），追加到 system_prompt |
| **人物档案** | 每个人有好感度（+2/次，封顶 800）、印象、昵称别名；QQ 与网页端身份会合并成一个人 |
| **主动开口** | 默认**关闭**。打开后按"意愿 × 许可"决定，群里 40 分钟最多一次，私聊同一个人 20 小时一次，且要好感度过线 |
| **日记与说说** | 晚上写日记（可配图），顺手备一条说说稿；送进发布插件的草稿箱，**最后一步永远由你确认** |
| **网页面板** | 一个页面看全部：四格状态、日程时间线、按人分块的记忆卡片、三个记录区、外观自定义 |

四层职责是刻意分开的：**日程给"意愿"，闸门给"许可"，模型给"措辞"，你给"开关"**。
把日程直接接到发送上，第二天就会变成到点冒泡。

## 二、安装

1. 把整个目录放到：

   ```
   <AstrBot>/data/plugins/astrbot_plugin_life_memory/
   ```

2. 在面板里重载插件（或重启 AstrBot）。首次启动会自动建库：

   ```
   <AstrBot>/data/plugin_data/astrbot_plugin_life_memory/memory.db
   ```

3. 打开插件配置，至少填这两项：

   | 配置 | 说明 |
   |---|---|
   | `master_ids` | 主人是谁。QQ 号和面板用户名都填进去，她会认这个身份 |
   | `extract_sessions` | 哪些**群**允许抽记忆（私聊由 `extract_private_all` 控制） |

4. 想让她主动说话，再把 `proactive_enabled` / `proactive_private_enabled` 打开。

> 装到别人的机器上时，`_conf_schema.json` 里的默认值是**原作者自己的号**，请先清空再填。

## 三、配置（24 项）

### 记忆抽取

| 键 | 默认 | 说明 |
|---|---|---|
| `extract_enabled` | `true` | 是否从对话里自动抽取记忆 |
| `extract_private_all` | `true` | 所有私聊都抽 |
| `extract_sessions` | `[]` | 额外要抽的**群**会话 id |
| `extract_hourly_limit` | `10` | 每个会话每小时最多抽几次（压账单） |

抽取是在 `on_llm_response` 之后做的：只看这一轮的"用户说了什么 + 她回了什么"，
同一个会话 60 秒内只抽一次，并且受上面的每小时上限约束。

### 主动开口

| 键 | 默认 | 说明 |
|---|---|---|
| `proactive_enabled` | `false` | 群里允许她主动开口 |
| `proactive_sessions` | `[]` | 允许开口的群 id |
| `proactive_private_enabled` | `false` | 私聊允许她来找人（要好感度过线） |

### 日记 / 说说 / 晚报

| 键 | 默认 | 说明 |
|---|---|---|
| `diary_hour` | `22:30` | 几点写当天日记 |
| `moment_auto` | `true` | 写完日记自动备一条说说稿 |
| `moment_forward_target` | `""` | 说说发布后转发到哪个群（留空不转发） |
| `diary_publish_hour` | `23:00` | 日记/说说自动发布的时间 |
| `diary_rewrite_hour` | `""` | 半成品重写的检查点（留空=发布前一小时） |
| `evening_report_enabled` | `true` | 睡前发一条晚报 |
| `evening_report_time` | `23:00` | 晚报时间 |
| `evening_report_target` | `""` | 晚报发给谁（账号 id） |

### 发送可靠性

| 键 | 默认 | 说明 |
|---|---|---|
| `online_check` | `true` | 发送前先探活（QQ 掉线时改走队列/丢弃） |
| `pending_expire_minutes` | `180` | 私聊待发消息的有效期，超时丢弃；`0`=不过期 |
| `retry_interval_seconds` | `300` | 补发队列扫描间隔，最小 30 秒 |

QQ 适配器在半连接状态下，`send_message` 会**成功返回但消息没出去**。所以主动消息
（晚报、私聊找人）发之前先用 `get_login_info` 探一次活：掉了就私聊排队、群聊丢弃，
不写"已发"骗自己。

### 角色（可以换成你自己的）

| 键 | 默认 | 说明 |
|---|---|---|
| `persona_name` | `大肥鱼` | 提示词里怎么称呼她 |
| `persona_desc` | `""` | 一句身份描述，替换掉"住在机器里的 AI 鲸鱼娘"；留空=保持出厂 |
| `persona_catch` | `白饭` | 她把 token 叫的那个词 |

这三个只在**提示词**里做替换，默认值等于原文，所以不改就一个字都不会变。
性格（傲娇、懒、怕麻烦）写在提示词正文里，是这个插件自带的味道；
要整套换掉，直接改 `dayplan_prompt.txt` 或源码里的提示词，没人拦你。

> 提示词里那一整套世界观（鲸鱼娘、鱼缸、白饭 = token）只影响"日程规划"和"说话口吻"。
> 换成猫娘、女仆、后辈都不需要改代码，改这三项就够。

### 其他

| 键 | 默认 | 说明 |
|---|---|---|
| `master_ids` | `[]` | 主人 id（QQ 号 + 面板用户名） |
| `timezone` | `Asia/Shanghai` | 时区。影响"今天"是哪天、几点算晚上 |
| `docs_dir` | `""` | `/文档` 命令去哪个目录找笔记；目录不在就提示一句 |

| `/说说` | `/看看说说` | 看最近几条说说稿 |
| `/发布 <编号>` | | 只送进发布插件的草稿箱，最后一步仍由你确认 |
| `/配图 <编号>` | | 重画一张（走生图插件的通用接口） |
| `/测配图` | `/配图测试` | 强制生成一张配图看看 |

| `/记一笔 <重要度> <内容>` | | 手动塞一条记忆 |

## 五、网页面板

插件带两个页面，在面板的插件页里打开：

- `app` —— 主面板（日常看这个）
- `diag` —— 诊断页（桥接、接口、字段对不对）

主面板包含：四格状态（她此刻 / 想不想说话 / 记得的事 / 人格字数）、日程时间线、
外观自定义（四套预设 + 五个颜色 + 背景图 + 压暗）、记忆区（按人分块、卡片横滑、
搜索/只看不顺/重要度筛选、点开可改摘要和重要度）、人物列表、以及三个可折叠的记录区
（她说过什么 / 主动开口 / 分身干的活）。

卡片左侧那条竖线的颜色就是情绪：**绿=正面，金=中性，珊瑚=负面**。

右上角三颗胶囊里，时间是只读的，中间是连接状态，「刷新」会重新拉一遍数据
（**只在页面侧刷新，不重载插件**）。

## 六、数据与备份

全部数据在：

```
data/plugin_data/astrbot_plugin_life_memory/
├── memory.db                 # 记忆、人物、日志（唯一的库）
├── theme.json                # 外观（含背景图 data URL，可能很大）
├── pending_messages.json     # 掉线时排队的私聊消息
├── backfill_state.json       # /回填网页历史 的进度
└── dayplan_prompt.txt        # 日程提示词（可手改，改完不用重载）
```

备份建议（库在写入中也能安全拷）：

```bash
sqlite3 memory.db "VACUUM INTO 'memory.db.bak'"
```

库里主要表：`life_day` / `life_block`（日程）、`event`（事件记忆）、`person` /
`person_alias`（人物与别名）、`speech_log`（她说过的话）、`proactive_log`（主动开口）、
`work_log`（分身干的活）、`message_log`、`wake_log`、`memory_use`、`memory_rollup`。

|---|---|---|

## 八、已知限制

- **只支持单实例**：一个进程里装一份。重载时旧实例的后台循环会自动退场（`_epoch` 自检），
  但仍不建议把同一份插件复制成两个目录同时启用。
- **QQ 探活只对 aiocqhttp 生效**：别的平台会当作一直在线，直接发。
- **群昵称粒度**：昵称从平台事件和 `platform_message_history` 取，取不到才退回 uid。
  模型推断出来的名字一律不用（会被注入带偏）。
- **记忆列表接口**：不筛选时一次最多返回 1000 条（够几千个事件用）。
  真到十万条量级需要改成"先取人物、再按人取事件"的两段式。
- **中文优先**：提示词和界面都是中文，非中文环境要自己改 `dayplan_prompt.txt` 和提示词。

## 九、排错

先看日志里带 `[life_memory]` 的行：

| 现象 | 先查 |
|---|---|
| 页面空白 / "桥接未注入" | 是不是从面板的插件页打开（iframe 里才有 `AstrBotPluginPage`） |
| 记忆一直是 0 条 | `extract_enabled`、会话是否在 `extract_sessions`、每小时上限是否用尽 |
| 她从不主动说话 | `proactive_enabled`、`proactive_sessions`、`/闸门` 看拒绝原因 |
| 晚报说"已发"但没收到 | `online_check` 是否开着；看日志有没有"掉线，改走队列" |
| 时间对不上 | `timezone` 配置；库里 UTC 存储、显示按本地时区 |
| `/文档` 说没有这份文档 | `docs_dir` 指对了没有，文件名是固定的 |

离线自检（不需要起 bot）：

```bash
python selftest.py
```

## 十、隐私

`memory.db` 里是**真实的聊天记忆**，`theme.json` 里可能有你上传的背景图（base64）。
分享这个插件给别人的时候，**只发代码，别连 `data/plugin_data/` 一起打包**。

## 十、与其它插件的接口

这三处是**跨插件**的，插件本身不 import 对方代码，只按"通用接口"打交道。
三处全都可缺，缺了对应功能降级，不影响别的东西。

### 1. 配图 → `astrbot_plugin_image_generation` 的通用接口

```python
meta   = context.get_registered_star("astrbot_plugin_image_generation")
client = meta.star_cls.public_api
result = await client.generate_image_files(
    prompt=..., source="life_memory", image_count=1,
    aspect_ratio="4:3", is_admin=True,
)
# 约定返回：result.ok / result.paths[0] / result.code / result.message
```

- **提示词**：`scenes.py` 内置四个时段 × 三个变体的场景描述（清晨/午后/傍晚/夜里的小屋），
  按日期轮换（同一天稳定，跨天会变），再按当时心情加一点冷暖修饰。
- **三条硬规矩**（写死在提示词尾部）：只拍风景静物、不出现人物、画面内不出现任何文字。
- **缺插件时**：`("", "")`，命令回「没画出来（生图插件未就绪或返回空）」，
  日记照写、稿子照出，只是没有图。

### 2. 发说说 → `astrbot_plugin_space_kit` 的草稿箱

直接写它的库（不调命令，避免版本差异）：

```sql
INSERT INTO drafts(text, source, subject_id, subject_name, forward_target,
                   created_at, forward_note, image_path)
VALUES (?, 'life_memory', '', '她的一天', ?, ?, ?, ?);

INSERT INTO events(kind, draft_id, detail, created_at)
VALUES ('draft_created', ?, ?, ?);
```

- **只写草稿，从不发布**。发布要主人自己 `/动态发 <id>`，最后一步永远是人点的。
- `source='life_memory'` 用来标记这条稿从哪来。
- **缺插件时**（`space.db` 不存在）：返回 `None`，命令提示「没能送进草稿箱（space_kit 库不在？）」。

### 3. 睡眠时段 → `astrbot_plugin_quiet_hours` 的配置

读 `data/config/astrbot_plugin_quiet_hours_config.json` 里的：

```json
{ "ranges": "23:30-07:00" }
```

支持 `"23:30-07:00,12:00-13:00"` 这种多段写法（只取第一段）。按文件 mtime 缓存，
改配置不用重载插件。

- **缺插件时**：退回内置默认 `23:30–07:00`（和 quiet_hours 的出厂值一致，
  所以从现象上看不出来——这个坑 10-26 踩过一次）。

### 4. 只读：AstrBot 核心库

`data/data_v4.db` 的 `platform_message_history`，用途只有两个：补昵称、回填网页历史。
用 `mode=ro` 打开，**不写一个字节**。
