# 静默时段 · astrbot_plugin_quiet_hours

到点自动把群里的回复压到最短，同时关掉插件指令通道。只在配置的时间窗口内生效，其余时间完全不干预。

为 AstrBot 设计，解决两个具体问题：夜里群里还有人聊，但不需要机器人长篇大论；以及夜间的一次普通对话，也想省掉每次都要付的工具定义开销。

## 特性

- **时段可配**：支持多段、跨午夜，如 `23:30-07:00,12:30-13:30`
- **四层压缩**：砍工具定义、换极简人格、裁上下文、限回复字数，四项独立开关
- **指令通道拦截**：静默期间除白名单外，插件指令不执行、不回复，避免刷屏与误触
- **平台隔离**：默认排除 `webchat`，自用的 WebUI 会话永远不会被静默
- **可临时解除**：管理员用一条指令提前结束静默，豁免存内存，重启自动失效

## 省在哪

按省下的量排序：

1. **砍工具定义** —— 工具 schema 常常比整段对话还长，插件越多越明显
2. **换掉人格提示词** —— 用约 80 token 的极简指令替换原人格，并清掉其他插件追加的内容
3. **只留最近 N 轮上下文** —— 默认 1 轮，旧对话不再重复计费
4. **按字数截断回复** —— 默认 60 字，超出部分不发送

参考量级：八个典型插件工具的定义合计约 2200 token，这是一次请求的固定成本，与聊什么无关。

## 安装

**从仓库安装**：AstrBot 插件页填本仓库地址。

**手动安装**：下载后把 `astrbot_plugin_quiet_hours` 整个目录放进 `data/plugins/`，重启或在插件页启用。

修改代码或配置后需要重载插件，时间段解析结果有缓存。

## 配置

### 时段与范围

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | 开 | 总开关 |
| `ranges` | `23:30-07:00` | 多段用英文逗号分隔 |
| `exclude_platforms` | `webchat` | 不受静默影响的平台。WebUI 聊天用 `webchat`，自用时建议保留 |
| `only_platforms` | 空 | 只对这些平台生效，空表示除排除项外全部生效 |
| `only_group_chat` | 关 | 只对群聊生效，私聊不压缩也不拦指令 |

跨午夜直接写，`23:30-07:00` 表示晚上十一点半到次日早上七点。

### 压缩

| 项 | 默认 | 说明 |
|---|---|---|
| `disable_tools` | 开 | 静默时段禁用工具调用 |
| `keep_tools` | 空 | 仍保留的工具白名单，逗号分隔。留空表示全部禁用 |
| `strip_persona` | 开 | 用极简指令替换系统提示词，并清除其他插件的追加内容 |
| `keep_context_turns` | 1 | 保留几轮上下文，0 为不带 |
| `max_reply_chars` | 60 | 回复字数上限，0 为不限 |

### 指令通道

| 项 | 默认 | 说明 |
|---|---|---|
| `block_commands` | 开 | 静默时段拦截插件指令 |
| `command_allowlist` | 三个静默指令 | 仍可用的指令，逗号分隔 |
| `block_hint` | 一句提示 | 指令被拦时的提示语，留空则完全不出声 |
| `hint_cooldown_seconds` | 60 | 同一会话内提示语的冷却 |

`command_allowlist` 务必保留 `静默状态`、`静默结束`、`静默开启`，否则静默期间无法自行解除。

## 指令

| 指令 | 权限 | 说明 |
|---|---|---|
| `/静默状态` | 管理员 | 是否静默中、剩余分钟、当前生效范围与各压缩项取值 |
| `/静默结束 [分钟]` | 管理员 | 提前结束。不带参数豁免到本段结束；也可写 `120`、`30分钟`、`2小时` |
| `/静默开启` | 管理员 | 取消豁免，立即回到配置判断 |

豁免只存在内存，不改配置文件，重启自动失效。

## 边界

- 只拦截 `LLM_RESULT` / `STREAMING_FINISH` 类型的回复，指令输出原样放行，不会被截断。
- 不改变模型本身，也不做缓存，纯请求期修改。
- 静默期间依赖工具的功能（联网、点歌、搜图）会失效，这是省 token 的代价；关闭工具后模型可能口头声称做过某事，实际没有。
- 常驻插件通过关键词或透传回复的内容（如表情包）不受指令拦截影响，但若它依赖工具，工具禁用后同样失效。
- 指令本身大多不经过 LLM，拦截它们省的不是 token，而是行为层面的安静。
- 若供应商支持 prompt caching 且工具块处于稳定前缀，日常重复请求本已命中缓存，静默时省下的实际费用会低于按 token 单价的估算。

## 已知问题

- 静默时段内模型不知道自己的工具已被禁用，偶尔会承诺"我去查一下"然后什么都没发生。`NIGHT_SYSTEM` 里可以针对自己的场景补一条约束。
